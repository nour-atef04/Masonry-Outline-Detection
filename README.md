# Masonary Outline Detection

Masonary Outline Detection is a local Streamlit application for identifying
brick regions in masonry images, previewing their boundaries, and exporting the
resulting outlines as DXF polylines.

The application uses a trained PyTorch U-Net model. It can process common
PNG/JPEG images and TIFF images, including large images processed in overlapping
tiles. The project also includes a PyInstaller configuration for creating a
standalone Windows executable.

## How the application works

### Model and inference

The network is a U-Net encoder-decoder implemented in `streamlit_app.py`. Its
encoder uses convolution, batch normalization, ReLU activations, and max
pooling. The decoder uses transposed convolutions and skip connections to
combine features from corresponding encoder stages. The final convolution
produces a single-channel brick probability map.

At startup, the application loads the state dictionary from `model.pth`, moves
the model to CUDA when a CUDA-capable PyTorch installation is available (or CPU
otherwise), and sets the model to evaluation mode.

Before inference, images are enhanced using CLAHE on the LAB lightness channel
and gamma correction. Optional bilateral filtering is available for preview
processing. The image is then resized so its longest side is at most 512
pixels, padded to dimensions compatible with the U-Net, normalized using
ImageNet channel statistics, and converted to a PyTorch tensor. The model output
is passed through a sigmoid to produce per-pixel probabilities.

### Segmentation and large images

The interface lets the user adjust the probability threshold and watershed
`h-minima` value. Post-processing thresholds the probability map, calculates a
distance transform, identifies watershed markers, and segments connected
regions. The boundaries between regions are shown as an overlay on the image.

For full-image processing, the application divides the image into overlapping
tiles. It runs inference on each tile and blends the overlapping probability
maps to reduce visible seams. A progress bar reports tile-processing progress.

TIFF uploads are read from their first page. For other supported formats, the
uploaded image is converted to RGB.

### User interface and DXF export

The Streamlit interface provides:

- Upload for PNG, JPG, JPEG, TIF, and TIFF files.
- Controls for gamma correction, CLAHE contrast, probability threshold, and
  watershed splitting.
- Optional bilateral filtering controls for preview processing.
- A drawing canvas for selecting a region to preview.
- Zoomable boundary previews and a separate full-image processing action.
- DXF smoothness controls to simplify contour polylines.
- DXF downloads for either the preview region or the full image.

DXF outlines are generated by finding external contours for each segmented
region, optionally simplifying their points with OpenCV, and writing closed
lightweight polylines with `ezdxf`.

## Run from source on Windows

The instructions below use Git Bash. Run them from this project directory:

```bash
cd "/Masonary Outline Detection"
```

Python 3.11 is recommended. Create and activate a virtual environment:

```bash
py -3.11 -m venv .venv
source .venv/Scripts/activate
```

If an existing `.venv` reports that Python cannot be found, it was created from
a Python installation that is no longer available. Rename that environment
before creating a new one (choose a backup name that does not already exist):

```bash
deactivate
mv .venv .venv-backup
py -3.11 -m venv .venv
source .venv/Scripts/activate
```

Install the application dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install streamlit numpy opencv-python pillow torch albumentations scipy scikit-image matplotlib ezdxf tifffile streamlit-drawable-canvas streamlit-image-zoom
```

Start the app from the project directory so it can find `model.pth`:

```bash
python -m streamlit run streamlit_app.py
```

Open <http://localhost:8501> if Streamlit does not open a browser
automatically. To stop the app, press `Ctrl+C` in the terminal.

## Build and run the Windows executable

First complete the virtual-environment and dependency setup above, then install
PyInstaller:

```bash
python -m pip install pyinstaller
```

From the project root, build the executable with the project hook enabled:

```bash
python -m PyInstaller --noconfirm --clean --onefile --name run --add-data "streamlit_app.py;." --add-data "model.pth;." --hidden-import torch --hidden-import torch._C --hidden-import torch.nn --hidden-import cv2 --hidden-import albumentations --hidden-import PIL --hidden-import skimage --hidden-import ezdxf --hidden-import streamlit_drawable_canvas --hidden-import streamlit_image_zoom --hidden-import streamlit.web.cli --additional-hooks-dir=hooks run.py
```

The custom hook in `hooks/hook-streamlit.py` collects the `skimage` submodules,
including `skimage.segmentation`, which PyInstaller may not detect through
Streamlit's dynamic imports. The build writes the executable to
`dist/run.exe`. Launch it from Git Bash with:

```bash
./dist/run.exe
```

The launcher starts Streamlit on port 8501. Keep its console window open while
using the app, and visit <http://localhost:8501> if a browser does not open.
Press `Ctrl+C` in the console to stop it.

The executable is built as a one-file bundle and includes the app script and
model weights. `build/` contains generated PyInstaller intermediate files and
can be regenerated by running the build command again. The checked-in
`build.bat` uses a machine-specific Python installation path; the command above
uses the active virtual environment instead.

## Project files

| Path | Purpose |
| --- | --- |
| `streamlit_app.py` | Streamlit interface, model definition, inference, segmentation, tiling, and DXF export. |
| `run.py` | Starts Streamlit with the bundled app when running as a PyInstaller executable. |
| `model.pth` | Trained U-Net model state dictionary required by the application. |
| `hooks/hook-streamlit.py` | PyInstaller hook for collecting Streamlit resources and dynamically imported modules, including `skimage`. |
| `run.spec`, `run_final.spec` | PyInstaller spec files from previous build configurations. |
| `build/` | Generated files from PyInstaller builds. |
| `dist/` | Packaged executable and distribution output. |
